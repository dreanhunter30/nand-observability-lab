# Финальный протокол перед оценкой публикации

Состав основной серии и seed сохраняются из PROTOCOL_RU.md: 120 схем, 8307 NAND; отдельные эталоны 128/512 NAND. Повтор выполняется в новой папке с отключённой загрузкой site-packages (`python -S`). Известные прежние агрегаты проверяются без подбора новых seed. Проверяется ввод независимых публичных JSON-наблюдений без нетлиста и MOS-счётчиков.

Дополнительный исчерпывающий опыт: два или три известных первичных входа; от одного до четырёх NAND для установления минимального числа элементов. Нет внешних констант, входы одного NAND могут совпадать, порядок его входов не различается, обратные связи исключены. В точном пространстве четырёх NAND все четыре обязаны быть предками единственного внешнего выхода. Это связность с выходом, а не обещание функциональной незаменимости каждого элемента. Внутренние имена анонимны: перебираются все их допустимые перестановки, внешний выход фиксирован. Первичные входы не переставляются.

Пять режимов наблюдаемости: полный внешний truth table; ещё один внутренний датчик; все внутренние датчики пассивно; все датчики и все одиночные вмешательства на каждом внешнем назначении; дополнительно все парные вмешательства. Планы одинаковы для всех кандидатов пространства и не используют скрытые связи. MOS-счётчики в этом опыте отсутствуют. Первичная оценка различает функциональный класс, топологию с точностью до внутренних переименований и точный граф по именованным каналам. Эти метрики не смешиваются.

Предварительный двухвходовый пример AND из четырёх NAND избыточен. В финальном опыте отдельно проверяется трёхвходовый AND и его минимальный размер, чтобы исследовать неоднозначность без предположения о лишних элементах. Результаты для четырёх элементов не обобщаются на произвольный размер.

Независимая проверка использует отдельный декартов перебор вариантов, матрицы смежности с кратностью ребра для изоморфизма и скалярные вмешательства для каждого именованного кандидата. Все файлы результата и кластеры кандидатов сохраняются.

Готовность к публикации оценивается по воспроизводимости, правдивости описания, сохранению неоднозначности, явным предпосылкам, примеру импорта данных, проверке некорректного ввода и переносимым командам запуска. Сравнение с HAL/ABC — только проверка позиционирования, без выдуманного сравнительного бенчмарка. Данные физического оборудования и научная приоритетность не заявляются. GitHub CI для Windows/Linux готовится, но удалённый успех до его запуска не заявляется.
